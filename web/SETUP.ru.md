# Онлайн-игра на Vercel: настройка и первый матч

В проект добавлен браузерный режим: **Online Duel → Create Room → Copy Invite Link**.
Друг открывает приглашение и нажимает **Join Room**. Устанавливать игру или вводить IP не нужно.

Для публикации нужны аккаунты Vercel, Upstash и Cloudflare. Сервисы ещё не подключены:
в текущей сессии сохранённый токен Vercel оказался недействительным. Локальные проверки
не заменяют матч с другом через разные сети и проверку опубликованной версии.

## 1. Создать хранилище комнат в Upstash

1. Зарегистрируйся в [Upstash Console](https://console.upstash.com/).
2. Открой **Redis → Create Database**. Назови базу `ninja-clash-rooms`.
3. Выбери регион поближе к региону серверной функции Vercel. Это влияет на скорость
   подключения к комнате; во время боя запросы к Redis не идут.
4. Выбери подходящий план. Для теста проверь доступность бесплатного тарифа и его лимиты
   в консоли перед созданием базы.
5. В созданной базе найди **Connect → REST** и скопируй значения
   `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
   Нужен обычный токен с записью, а не Read Only.

Инструкции провайдера: [создание базы](https://upstash.com/docs/redis/overall/getstarted),
[REST URL и токен](https://upstash.com/docs/redis/features/restapi).

## 2. Подключить резервное соединение Cloudflare TURN

1. Зарегистрируйся в [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. Найди продукт **Realtime / TURN** в панели или поиске продуктов. Названия разделов
   могут меняться; ориентируйся на [официальную страницу создания TURN-ключа](https://developers.cloudflare.com/realtime/turn/generate-credentials/).
3. Создай TURN-ключ для `ninja-clash` и сохрани **TURN Key ID** и относящийся к нему
   **API Token**. Это отдельные данные TURN, не Global API Key аккаунта.
4. Ознакомься с условиями оплаты TURN-трафика в панели перед подключением.

Ключ позволяет серверу выдавать временные данные подключения. Долгосрочный ключ
не попадает в игру. Временные данные выдаются на четыре часа; для более долгой игровой
сессии создавай новую комнату. Домашние роутеры и проброс портов настраивать не нужно.

## 3. Добавить четыре переменные в Vercel

Открой проект **ninja-clash → Settings → Environment Variables** и добавь:

| Имя переменной | Значение |
|---|---|
| `UPSTASH_REDIS_REST_URL` | REST URL базы из Upstash |
| `UPSTASH_REDIS_REST_TOKEN` | Токен базы с правом записи |
| `CLOUDFLARE_TURN_KEY_ID` | ID созданного TURN-ключа |
| `CLOUDFLARE_TURN_API_TOKEN` | API Token этого TURN-ключа |

Выбери окружения **Production** и **Preview**, чтобы работали и основной сайт,
и тестовые публикации. Ключи не нужно добавлять в исходники, отправлять другу или в чат.

Изменения переменных применяются только к новой публикации:
[инструкция Vercel](https://vercel.com/docs/environment-variables/managing-environment-variables).

## 4. Собрать и опубликовать текущую игру

На этом Mac уже установлены Godot 4.6.2 и шаблоны Web. Открой терминал:

```sh
cd /Users/a88/IdeaProjects/minu-mang/web
npm ci
npm run export
```

Команда экспортирует **release**-сборку игры и складывает вместе с ней сервер комнат
и конфигурацию Vercel в `build/ninja-clash`. Используй именно эту команду:
обычный экспорт из Godot не копирует серверную часть.

Затем обнови вход и создай тестовую публикацию:

```sh
cd /Users/a88/IdeaProjects/minu-mang/build/ninja-clash
npx vercel login
npx vercel deploy
```

Папка уже связана с проектом `ninja-clash`. Если CLI предложит привязку, выбери
существующий проект. Для него нужен пресет **Other**, без отдельной команды сборки,
с каталогом вывода **public**; эти значения также заданы в подготовленном `vercel.json`.
Серверный обработчик лежит в `api/rooms.js` и публикуется как Vercel Function.

Проверь выданную Preview-ссылку. Если Vercel просит друга войти в аккаунт, это защита
Preview-публикации, а не ошибка игры; для общедоступного матча используй Production.

После проверки опубликуй на основном адресе:

```sh
npx vercel deploy --prod
```

Публиковать из корня GitHub-репозитория с текущими настройками не следует:
готовая папка размещения — `build/ninja-clash`. Автоматический деплой из Git здесь
не настраивался. Документация: [Vercel login](https://vercel.com/docs/cli/login).

## 5. Провести первый удалённый матч

1. Оба откройте свежую Production-ссылку в Chrome. Для первого теста используйте
   компьютеры и отдельное окно браузера для игры.
2. Ты: **Online Duel → Create Room → Copy Invite Link**.
3. Отправь другу скопированную ссылку вида `https://ninja-clash.vercel.app/#room=…`.
   Если копирование заблокировано браузером, выдели ссылку в поле под кнопками и скопируй её вручную.
4. Друг: открыть ссылку → **Join Room**. Затем оба выбираете персонажей,
   ты выбираешь карту, и вы закрываете подсказку управления.
5. Проверьте движение, прыжки, броски, попадания и изменение счёта с обеих сторон.
6. Закрой окно хоста: гость должен вернуться в онлайн-меню с сообщением об отключении.
7. Проверьте повторное подключение через **новую** комнату.

Для проверки разных сетей второй компьютер можно подключить через мобильную точку доступа.
Субъективно оцените, удобно ли гостю управлять персонажем: прямое или резервное
соединение не устраняет задержку интернета. Предсказание движения клиента пока не реализовано.

## Если не подключается

| Сообщение / симптом | Что проверить |
|---|---|
| `ONLINE SERVICE UNAVAILABLE` | Все четыре переменные сохранены для нужного окружения; после их добавления сделан новый деплой; TURN-ключ действителен |
| `ROOM EXPIRED OR NOT FOUND` | Приглашение создано на той же публикации; ожидание комнаты ограничено 10 минутами |
| `HOST IS NO LONGER WAITING` | Хост закрыл или надолго скрыл вкладку; создать новую комнату |
| `ROOM IS FULL` | По приглашению уже вошёл другой гость; создать новую комнату |
| `CONNECTION TIMED OUT` | Проверить TURN, ограничения корпоративной сети и повторить на другой сети |
| Чёрный экран / SharedArrayBuffer | Публикация должна содержать подготовленный `vercel.json` с COOP/COEP-заголовками |
| Гость чувствует задержку | Проверить качество связи; браузер хоста должен оставаться активным |

Для проверки ключей на своей машине можно создать `web/.env.local` по образцу
`web/.env.example` и выполнить из `web`:

```sh
node --env-file=.env.local tools/check-config.mjs
```

Команда проверяет доступ к Redis и выпуск временных TURN-данных, не печатая ключи.
Она не проверяет прохождение игрового трафика через TURN.

## Локальные проверки разработчика

```sh
cd /Users/a88/IdeaProjects/minu-mang/web
npm ci
npm test
npm run export -- --debug
npm run test:browser
```

Браузерные тесты используют Chrome, настоящий экспорт Godot и реальные нажатия клавиш.
В обычном запуске тест принудительного TURN пропускается. Для полной локальной проверки
нужен `coturn` в PATH (на macOS: `brew install coturn`):

```sh
NINJA_TEST_TURN=1 npm run test:browser
```

Тест сам запускает временный TURN на loopback и выключает его после завершения.
Ни этот TURN, ни локальное хранилище в памяти не предназначены для публикации.
Для проверки Redis-скриптов `npm test` использует установленный `redis-server`;
при его отсутствии соответствующий тест отмечается как пропущенный.

После debug-тестов **снова выполни `npm run export` перед публикацией**, чтобы отправить
release-сборку без активной тестовой телеметрии. Настольная игра продолжает использовать ENet;
комнаты браузерной версии и подключение настольной версии по IP — разные режимы.
